- (decision) Why: portfolio demo proving ability to design agents that self-check and recover from mistakes, not code-gen breadth. Dual audience: recruiter (30s skim) + engineer/hiring manager reading orchestration code.
- (capability) CAP-1 NL-to-Compose core generation loop. Intent: accept NL UI description, generate valid Jetpack Compose/Kotlin code via single-LLM-call ui_generator_agent (AD-1). Success: 3 curated demo prompts each produce compiling Compose code end-to-end without manual intervention.
- (capability) CAP-2 Agent trace panel. Intent: every graph node appends a structured TraceStep (AD-4) so the UI can show real pipeline reasoning as it happens. Success: for any run, the trace panel shows one entry per node actually executed (ui_generator, validator, accessibility_reviewer, ui_reviewer, output) - no fictitious stages.
- (capability) CAP-3 Self-review verdict. Intent: accessibility + Material 3 design checks emit structured CheckResult{check,status,message} (AD-3), not prose. Success: verdict UI renders explicit pass/fail/warn per check with no string-sniffing.
- (capability) CAP-4 Self-correcting validation loop. Intent: validator runs as an in-graph node (AD-2); on failure, conditional edge routes back to ui_generator with last_validation_errors in the regeneration prompt (AD-5), bounded to 2 retries. Success: a demo prompt engineered to fail validation once visibly loops back, increments retry_count, and the trace shows the fix applied within 2 retries.
- (capability) CAP-5 [Should] HTML visual preview alongside code - already implemented (streamlit_interface.py generate_preview_html). Intent: visual structural rendering of generated UI. Success: preview renders for every generated UI with no manual step.
- (capability) CAP-6 [Should] Figma input via MCP - already implemented. Intent: accept a Figma file/frame reference as alternative input source. Success: a Figma-sourced input completes a generation run through the same pipeline as NL input.
- (capability) CAP-7 [Should] Streamlit chat-based iterative refinement - already implemented. Intent: refine previously generated code conversationally. Success: a follow-up instruction updates the prior code without a full restart.
- (capability) CAP-8 [Could] Curated fuzzy-style sample prompts. Intent: ship 3 demo prompts mixing concrete requirements with subjective style cues to demonstrate genuine interpretation (not template-fill). Success: 3 prompts exist, documented, and are the same 3 used in CAP-1's success signal.
- (constraint) No new external dependencies - build on existing stack (langgraph>=1.0.3, streamlit>=1.39.0, langchain-core/openai/ollama, mcp). langgraph>=1.0.3 already supports add_conditional_edges needed for CAP-4.
- (constraint) Secrets (API keys, Figma tokens) stay in .env, never committed - repo is public on GitHub.
- (constraint) Real Kotlin compilation stays a heuristic (GradleMCP brace/paren counting, not kotlinc/Gradle invocation) - must be documented as a known limitation, never silently implied as real compilation.
- (constraint) Single-LLM-call generation retained - no reintroduced Intent Parser/Layout Planner nodes (AD-1 adopted); README pipeline diagram must be corrected to match real graph nodes.
- (constraint) Shared shapes bend implementation: CheckResult{check,status:pass|fail|warn,message} for all check-producing nodes (AD-3); TraceStep{node,summary,detail} appended to state['trace'] (AD-4); retry_count bounded to 2 with last_validation_errors carried into regeneration prompt (AD-2/AD-5).
- (note) Non-goals: staged 'break it live' failure theatrics; new input modalities beyond NL text and Figma; production-grade hardening (auth, multi-user, persistent storage beyond session).
- (decision) Success signal (overall): 3 curated demo prompts each run end-to-end in a single pass producing compiling Compose code + populated trace + pass/fail verdict, reproducibly, without manual intervention; plus one off-script/ad-hoc prompt also completes without breaking the pipeline (counter-metric against over-fitting to curated prompts).

- (constraint) Added on self-validate pass 2: generation loop must feel live/interactive (PRD NFR latency, initially missed); scope-ambiguity heuristic (PRD Guiding Principle) - favor exposing existing self-correction over new capabilities.
